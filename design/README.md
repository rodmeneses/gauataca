# design/ — snapshot of the Claude Design source

`Guataca.dc.html` is the exact file the app was ported from (Claude Design project
`d7a06c72-dd08-48b8-a34d-cc51a3ff6930`, exported 2026-08-25). `support.js` is its runtime, generated by Claude Design —
do not edit either by hand.

## Why it is in the repo

So that design iterations are **diffable**. When the prototype is updated in Claude Design, re-export
`Guataca.dc.html` over this one and `git diff design/Guataca.dc.html` shows precisely which template regions and
which `renderVals()` bindings changed — that diff is the delta an agent implements, instead of re-porting everything.
See [`docs/iterating.md`](../docs/iterating.md) for the workflow and the prompts.

## Viewing it

The file renders standalone (it loads React from a CDN through `support.js`); it only needs to be served over HTTP:

```sh
python3 -m http.server 5177 --directory design
# then open http://localhost:5177/Guataca.dc.html
```

Useful for side-by-side screenshots with `npm run dev` on port 5173.

## Structure of the file

- lines ~34–1526: the template — HTML with `{{ binding }}` text, `<sc-if value="{{ cond }}">`, `<sc-for list="{{ arr }}" as="x">`, `style-hover="…"`, `onClick="{{ fn }}"`.
- line ~1528: `<script data-dc-script data-props="…">` — the six tweak definitions (bandName, initialLang, initialRole, startView, showTour, staleDays).
- lines ~1529–2345: `class Component extends DCLogic` — mock data (`MEMBERS`, `RAW_SONGS`, `EVENTS`, `TX`, `GEAR`, `THREADS`), the `T` dictionary, `state`, helpers, and `renderVals()` which defines every binding the template uses.

The React port maps these 1:1 — see `docs/implementation.md` §2.
